# Version 1 — Change Log

This document records every modification made to the Sniffr codebase in this working session, grouped by feature area. It covers frontend, backend, and database changes, plus manual steps still required on the live Supabase database.

---

## ⚠️ Manual steps required (not automated)

`runMigrations()` in `server/db/migrations.js` is dead code — it is never invoked at server startup. All schema changes below must be applied to the live Supabase database by hand.

1. **PawPrint Verification (enable-by-link) columns:**
   ```sql
   ALTER TABLE users ADD COLUMN IF NOT EXISTS pawprint_verify_token_hash TEXT;
   ALTER TABLE users ADD COLUMN IF NOT EXISTS pawprint_verify_expires_at TIMESTAMP;
   ```
2. **Rate Sniffr table** (already applied by the user during this session):
   ```sql
   CREATE TABLE IF NOT EXISTS public.app_ratings (
     id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
     user_id INTEGER UNIQUE REFERENCES public.users(id) ON DELETE CASCADE,
     rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
     created_at TIMESTAMPTZ DEFAULT NOW(),
     updated_at TIMESTAMPTZ DEFAULT NOW()
   );
   ```
3. Restart the server after any of the above and after every backend code change in this log — `node index.js` / `npm run server`.

## 1. Responsive UI/UX refinement

**Files:** `client/src/pages/HomePage.jsx`, `ChatPage.jsx`, `ProfilePage.jsx`, `SpotlightPage.jsx`, `MeetPage.jsx`, `components/CreatePostModal.jsx`, `components/SharedPostViewerModal.jsx`, `components/NotificationPostViewerModal.jsx`, `components/GalleryViewerModal.jsx`, `client/src/index.css`

- **Header/sidebar overlap at tablet widths**: every page's fixed mobile header (`lg:hidden`, `fixed top-0 w-full`) ignored the 80px icon-rail sidebar shown at 768–1023px, drawing on top of it. Changed to `left-0 right-0 md:left-20` on all 5 pages so the header stops at the sidebar's edge.
- **Post image cropping bug**: post/media containers used `w-full object-cover` with a fixed `maxHeight: '480px'` — as viewport width grew, the box's aspect ratio changed and `object-cover` cropped progressively more of the image. Changed to `object-contain` with `maxHeight: 'min(480px, 70vh)'` across the feed, `SharedPostViewerModal`, `NotificationPostViewerModal`, `GalleryViewerModal`, and the `CreatePostModal` upload preview — full image now always visible, letterboxed instead of cropped. Avatar/grid thumbnails elsewhere were left untouched (intentional crops).
- **Removed forced whitespace**: tightened mobile spacing (`space-y-8` → `space-y-5 sm:space-y-6 lg:space-y-8`, `p-5` → `p-4 sm:p-5`, action-row `gap-7` → `gap-5 sm:gap-7`) and added `min-w-0`/`truncate`/`flex-wrap` guards on the post header row so long names can't force overlap.

## 4. PawCircle (Community) overhaul

**Files:** `client/src/pages/CommunityPage.jsx`, `client/src/components/PawCircleTab.jsx`, `client/src/components/PawShape.jsx` (new), `client/src/index.css`, `server/models/CommunityRepository.js`, `server/routes/communities.js`

- **Paw-shaped community avatars**: new `PawShape.jsx` exports a reusable SVG `clipPath` (one pad + four toes, normalized via `objectBoundingBox` so it scales to any element size). Applied to all community cover images in `PawCircleTab.jsx` and `CommunityPage.jsx`'s Details tab.
- **Messages now appear instantly**: `handleSendMessage` previously never added the sent message to local state, relying entirely on a socket echo — fixed to append the server's response immediately. `handleMediaUpload` had a worse bug: it double-inserted the message (once via REST, once via a redundant `socket.emit('send_community_message', ...)`) and reloaded the entire page afterward — fixed to append once, no duplicate, no reload.
- **Chatbox-only scrolling**: replaced `scrollIntoView()` (which can drag ancestor/page scroll along with it) with directly setting `scrollTop` on the chat pane's own ref.
- **Removed forced empty space**: the tab-content wrapper forced `min-h-[460px]` on every tab, not just Chat — now only applied to the Chat tab.
- **Owner-leave auto-deletes empty circles**: `CommunityRepository.leave()` now deletes the community outright (child rows cascade via existing FK constraints) if the leaving user is the owner and no members remain — previously left an orphaned, permanently-unusable circle behind. The retract-confirmation modal detects this case ahead of time and warns explicitly, with matching icon/copy/button color. Route (`POST /communities/:id/leave`) returns a `deleted` flag; frontend toast reflects it.
- **Member profile preview (half → full)**: tapping a member row opens a modal. If not matched (checked against `/matches`), shows a blurred/locked preview with basic info; once matched, shows full info (breed/bio) + "View Full Profile" button. Required adding `pet_id`, `breed_name`, `bio` to `getMembers`/`getMembersPaginated` SQL.
- **Unified header/tab-bar card**: merged the back-button/name/3-dot-menu header and the tab bar into a single rounded, sticky card instead of two visually separated blocks.

## 6. Email verification & PawPrint Verification (enable-by-link)

**Files:** `server/routes/auth.js`, `server/models/UserRepository.js`, `server/utils/mailer.js`, `server/db/migrations.js`, `client/src/pages/VerifyPawprintPage.jsx` (new), `client/src/App.jsx`, `client/src/components/settings/SettingsModals.jsx`

- **Token hashing**: account email-verification tokens and password-reset tokens are now SHA-256 hashed before storage (`hashToken()` helper) — only the hash lives in the DB; the raw token exists only in the emailed link.
- **PawPrint enable flow replaced**: instead of a 6-digit code, enabling PawPrint now sends a "Verify & Enable PawPrint" email link (1-hour, single-use, hashed token). Login-time 2FA (the 6-digit code, `/2fa/verify-login`, `/2fa/resend-code`) is untouched.
  - New routes: `POST /auth/pawprint/send-verify-link` (rejects with `EMAIL_NOT_VERIFIED` if the account email isn't verified; 60s cooldown), `GET /auth/pawprint/verify-link` (validates + enables + emits `pawprint_enabled` socket event).
  - New `UserRepository` methods: `setPawprintVerifyToken`, `findByPawprintVerifyTokenHash`, `clearPawprintVerifyToken`.
  - New email template: `sendPawprintVerifyLinkEmail`.
  - New page `VerifyPawprintPage.jsx` + route `/verify-pawprint`.
  - `SettingsModals.jsx`'s PawPrint modal rewritten with 3 states: email-not-verified gate → send-link → "check your inbox" (resend + cooldown). Live-updates and auto-closes via the `pawprint_enabled` socket event, wired in `App.jsx`'s `MainLayout`.
- **Verification reminder**: `GET /auth/me` now fires a best-effort, non-blocking in-app notification if the account is unverified and >24h old, deduped by checking for an existing reminder in the notifications table within the last 7 days (no new column needed).
- Documented previously-undocumented columns (`email_verified`, `email_verify_token`, `email_verify_expires_at`) and the two new PawPrint columns in `migrations.js`.

## 7. Live location on Me page

**File:** `client/src/pages/ProfilePage.jsx`

- Root cause: the live-location effect requested geolocation permission automatically on page mount, with no user gesture behind it — several browsers (notably iOS Safari) silently ignore/timeout a permission prompt that isn't triggered by a direct click, so it never displayed.
- Fixed: the background effect now only silently reads location if permission was **already** granted; it never triggers the prompt itself. A new `handleDetectLiveLocation`, wired directly to button clicks, does the actual permission request + GPS read + reverse-geocode.
- The location info-popup's action button now calls this handler directly instead of opening the full Edit Profile modal.
- Added a small refresh icon next to a displayed location so it can be re-detected anytime without going through Edit Profile.

## 8. Signup/loading performance fixes

**Files:** `server/routes/auth.js`, `server/utils/mailer.js`, `client/src/App.jsx`

- **Root cause of "signup took long / required a manual refresh"**: `auth.js` was `await`-ing email delivery (welcome/verification email) as part of the signup response. If SMTP was slow or misconfigured, the account was already committed to the DB, but the HTTP response hung until mail delivery resolved/timed out — the browser never got its session back to apply.
- Made all email sends fire-and-forget (no longer awaited by the caller): signup welcome email, resend-verification, PawPrint verify-link, and all 3 PawPrint login-code sends.
- Added bounded SMTP timeouts (`connectionTimeout`/`greetingTimeout`/`socketTimeout`) to the mailer transporter so a bad host fails fast even in the background.
- **Converted all synchronous bcrypt calls to async** (`bcrypt.hashSync`/`compareSync` → `bcrypt.hash`/`compare`) across signup, social-complete, login, reset-password, and change-password — synchronous hashing blocks Node's single-threaded event loop, meaning one user signing in could stall every other concurrent request (page loads, chat, everything) for the duration of the hash.
- Removed the flat 2.5-second splash screen shown on every single app load/refresh regardless of how fast the session check resolved (`App.jsx`) — reduced to a 500ms branding flash.

## 9. Chat search fix

**File:** `client/src/pages/ChatPage.jsx`

- `handleSearchChange` debounced via `setTimeout` but never actually cancelled the previous pending timer (its returned cleanup function was dead code — this is a plain event handler, not a `useEffect`). Typing fast fired an overlapping search request per keystroke, and whichever response arrived last — not necessarily the one for the final query — silently overwrote the results.
- Fixed with a ref-held timer (cancels the previous pending search) plus a request-id guard that discards any late/out-of-order response.

## 10. Rate Sniffr (Supabase-backed)

**Files:** `server/models/RatingRepository.js` (new), `server/routes/ratings.js` (new), `server/index.js`, `server/db/migrations.js`, `client/src/components/settings/SettingsModals.jsx`

- Previously fake — "Submit Rating" only set local component state, nothing persisted.
- New `app_ratings` table: one row per user (`UNIQUE` constraint), `INSERT ... ON CONFLICT (user_id) DO UPDATE` upsert semantics — resubmitting updates in place rather than duplicating.
- `POST /api/ratings` (authenticated, rate-limited) upserts the rating, then broadcasts the new aggregate to **every connected client** via `io.emit('app_rating_updated', ...)`.
- `GET /api/ratings` returns the live average, count, and the caller's own existing rating.
- Settings modal fetches the real aggregate + prior rating on open (pre-filling stars, showing "Update Rating" if already rated), displays the live average, and listens for the socket broadcast so the number updates instantly for anyone with the modal open — including users who didn't just rate it themselves.
